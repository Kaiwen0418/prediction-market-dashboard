# 30天复盘区间连续性

调查采集改为按入选市场补采冻结的30天区间，停止广域成交采集和旧热数据迁移任务。先保护最多20个入选档案，计算任务仍最多两个在途。保留市场目录发现和已有排除规则。

每个市场每次只采一页，持久保存分页进度，移除32页总量截断。Kalshi 当前、历史公共接口都走完后，再独立遍历整个区间一次。核对逐页成交内容摘要、成交数量及扫描内重复成交次数，成功后写入 verified_api_interval。第二次遍历前等待60秒；若来源改变，最多追加到四次遍历，仍不稳定则标记 continuity_unresolved，保留输入等待修复。源错误连续三次同样阻止进入分析。

验收证明的是固定区间内两次完整 API 遍历一致。上游未公开的成交与稳定遗漏仍需其他来源对账。区块链数据本批未接入。

分页清单事务绑定原始响应、归档和检查点。原始 FIFO 与归档清理跳过清单引用的证据。受保护档案不会因容量压力被逐条截断；90天保留期结束时删除父档案并整体解除保护。容量不足将阻止采集，需缩小准入或扩容。历史报告尚未通过此检查时 API 标记 legacy_unverified，钱包统计只纳入通过新验收的报告。

数据库准入预算扩大至40 GiB，原始响应15 GiB，紧凑成交10 GiB（计入数据库预算）。部署前确认主机空闲约280 GiB。WAL和临时空间另计，应用预算允许有限单次写入超出。

分析输入仍有内存保护。单片超预算时缩小时间片；最低片段仍超限则标记 needs_analysis_capacity，整个档案保留，等待流式分析支持，不产生跳过该片段后的完成报告。空成交区间通过两次遍历也可验收。

新接口详情包含 continuity 与 page_manifest。旧版 review_max_pages 配置保留兼容，其总页数限制已从补采逻辑移除。

## 有成交准入

目录明确报告成交量为零的市场以 reported_zero_activity 原因退出正式队列；未知成交量仍保留资格。调度查询直接跳过明确零成交，历史队列通过每轮100条的策略更新逐步清理。后续目录若显示成交量增加，允许新版本重新入队。保留低成交但非零市场，避免仅按热门程度筛选。

## 浮动准入

累计20个档案的限制已移除。每轮使用容量检查缓存和归档记账，按可用字节决定是否继续准入，同时保留最多两个在途任务。为每个在途任务预留数据库512 MiB、原始文件256 MiB和紧凑归档256 MiB，准入水位分别为数据库活跃空间70%/物理空间90%、原始文件70%、归档75%。这些是保守工作余量，实际采集仍由容量守卫约束。空间回收或扩容后自动恢复接纳，正在保护的证据维持保留规则。

双遍历没有观察到成交的档案标记 no_observed_trades 并保留证据。后续目录成交量增加时可以重新入队。非零成交量优先于未知成交量。
