# 结算后交易领先复盘：P0 / P1

2026-11-04。依据用户最新要求，调查服务默认改为 retrospective 模式，停止自动实时深采、选池、短窗口报警、scout、钱包在线积累和在线聚合任务。不改看板前端，不自动交易。

## 数据流

双平台广域 REST 成交 → 标准化热数据 + 紧凑归档 → 已结算合约确认 → 有界补采 → 按时间分片复盘 → 独立 API / Markdown 报告。

使用同一个 `surveillance_markets` 目录。关闭/结算扫描不再创建第二套市场目录。没有事件类别、成交量或深采名单准入限制；组合合约、非最终状态和不明确结算结果不生成自动最终复盘。关闭不等于结算。规则、结算结果变化会形成新的复盘版本，旧版标记 superseded；再打开/争议状态会撤销先前最终状态。

- 每个平台的目录 head 每 5 分钟检查首 100 个合约，仅代表头部样本。
- 独立持久游标继续遍历完整关闭目录、Kalshi 当前结算目录及历史目录，每次 100 个、间隔 5 分钟。目录尚未遍历完时明确 pending，不宣称全平台完整覆盖。
- 默认只留研究保留期内的市场；目录计数记录保留期外记录。较旧但最近才结算的市场按实际结算时间判断。
- 补采同时读取 Kalshi 当前和历史公共成交，按公开 trade ID 去重；不构建 Kalshi 账户画像。Polymarket 保留扫描内相同成交的出现次数，不假装拥有独立链上 fill ID。
- 最近成交保留用于将来结算后的复盘；旧接口已经删除的数据不能保证补回。

## 有界任务和存储

- 同时最多 2 个在途复盘任务，双平台公平分配，实际仍由一个 worker 串行执行。
- 每次最多采 1 页、每个复盘最多 32 页；约 15 秒后续接。限额到达保留 `page_budget_exhausted`，不伪装完成全部历史。
- 默认回看开盘至结算之间最近 30 天。更早历史排除会明确标记。研究归档最多保留 90 天，同时受容量上限约束，不能保证 90 天全部存得下。
- 新增紧凑标准化档案预算 2 GiB、复盘/覆盖摘要预算 512 MiB，包含在原数据库预算内。按数据库中记录的 tuple 大小加每行 256 字节估算记账；它不是精确的物理磁盘配额。原 20 GiB 数据库 / 5 GiB 原始文件准入上限继续有效，WAL、临时文件等仍需额外空间。
- 每 30 秒运行有界档案清理，每个表每轮最多删除 500 条。原始证据 FIFO 不会连带删除紧凑档案；档案自身淘汰会撤销相关历史采样覆盖。
- 归档保留标准化成交、来源和原始响应哈希，可以重算；它不替代原始 HTTP 响应。API 动态报告原始证据是否已过期。
- 旧热数据按每批 10 个 receipt、每 5 秒迁入归档，只迁移仍存在的数据，不能恢复过去已经覆盖的数据。
- 每个分析片段默认 24 小时，带 4 小时前置上下文及最多 1 小时后续价格。超 50,000 笔或引用/扫描预算则缩短到最低 1 小时，仍超限时记录 unavailable，不产出截断评分。
- 队列、目录页、成交页、分片和进度有事务与租约保护；重启继续游标。

## 检测含义

`leadlag-v1` 是事后描述性检测，不是校准后的内幕分数：

1. 每结果方向独立生成 5 分钟成交价中位数，缺失桶不填充。
2. 比较 5 分钟、30 分钟、2 小时变化，基线至少 6 个连续桶；基线和确认桶每桶至少 3 笔。
3. 初始变化阈值取 10 个百分点与 6 倍基线 MAD 的较大值，并要求后一桶维持至少 70% 变化。
4. 从首次可观测偏离确定“改价开始区间”，不虚构秒级开始时间。连续跳变合并，时间片之间使用上下文避免重复。
5. 检查改价前 1 小时的全部可归因钱包，计算提前买入/卖出、前置成交金额占比、5 分钟及 1 小时交易后价格变化，纳入该窗口内相反方向交易。
6. 同时记录钱包在改价过程中的成交占比；达到 25% 或无法计算时提示自身冲击未排除。这不是因果检验，低于阈值也不能证明不存在自身影响。
7. 单片最多列 40 个片段、每片段 20 个钱包、每钱包 5 个成交引用，均报告省略数量。输入归档和摘要仍可用于重新计算。

结算结果仅用于启动任务，不参与领先检测评分。报告中 anomaly / evidence / priority 分数暂为 null。买后上涨、卖后下跌衡量的是价格择时，不是完整利润。尚未实现跨事件钱包排名、同类对照统计、自动公告、跨平台等价合约映射或内幕结论。

## API

均沿用 Bearer token：

- `GET /retrospectives/status`：模式、队列、归档预算、目录遍历状态。
- `GET /retrospectives`：分页列出处理状态与范围。
- `GET /retrospectives/{id}`：冻结结算规则与分页分片，动态检查原始响应是否仍在。
- `GET /retrospectives/{id}/report`：每页一个分片的 Markdown 报告，使用 next_after 翻页。
- `POST /retrospectives/{id}/slices/{slice_id}/replay`：以分片归档知识时间重读并验证完整输入摘要；输入变化/过期返回 409，超预算返回 413。

未来信息仅用于显式 retrospective 报告，不改变旧在线案件分数，也不声称这些候选曾在当时报警。

## 验证与测量

新增测试覆盖：买入领先、提前卖出、自身影响提示、价格反转、缺口、结果方向隔离、结算版本/撤销、分页重启与相同成交次数、Kalshi 两类接口去重、原始 FIFO 后归档重算、档案容量淘汰与覆盖撤销、停止在线任务及 API。

完整调查测试 106 项通过。真实接口隔离测试取得 Polymarket 10 笔、Kalshi 248 笔成交并生成报告，两例均无满足当前阈值的片段；不能据此评价准确率。5 万笔合成基准归档约 6.34 MiB、读取 0.21 秒、分析 0.81 秒、整个进程峰值 232.5 MiB。

实测结果见同目录 `retrospective-benchmark-2026-11-04.json` 和 `retrospective-smoke-2026-11-04.json`。基准使用独立数据库 schema、单核 / 768 MiB 容器，5 万笔合成成交和 300 个钱包；不代表真实流量的压缩率、准确率或全平台吞吐。测试资源在完成后删除。
