# 公告复盘与钱包自身基线：实施记录

2026-10-29。承接传统市场监察研究，首版实现事件驱动复盘、原生事件归组、版本化五分钟统计和限额钱包补采。仍是独立 Python/PG 服务，不接前端、不自动交易。

## 已落地

- 已核验的手动信息录入触发持久化 `event_review` 任务；1h、6h、1d、3d、7d 回看，公告边界的零碎五分钟片段从原始标准化成交精确计算。公开时间与实际可知时间独立。
- 仅按平台原生 event ID 归组，保持合约/结果独立统计；同事件、同公告时间生成一个版本化案件，人工复核状态保留。不按标题猜跨平台等价关系。大事件支持显式单合约模式。
- 有成交才写五分钟桶；迟到成交追加带真实 `known_at` 的版本，重读不改历史。缺失、等待聚合、完整零成交 API 观察分开。工作队列每次最多处理 500 个桶，30 秒再运行；首次从已有七日成交重建，历史调查另用 CLI 指定范围。
- Polymarket 自动线索可补采一个窗口内现金流较大的公开钱包。全局每小时最多四个，每个最多两页/1,000 笔；七日自身历史至少 20 笔、跨两天且分页完成，才提供当前金额相对自身 P95 的比值。历史不足或截断为 null。Kalshi 不建立账户画像。
- 调查信息、原始引用与钱包补充追加案件版本，保留原告警分数。新表接入七日保留及原有数据库 20 GiB / raw 5 GiB 的容量回收。原始证据覆盖后清除依赖汇总，容量仍是准入预算而非文件系统硬配额。

## 性能实测

在目标机器 API 容器（1 CPU、512 MiB）及实际 PostgreSQL 17 中建立一次性隔离 schema，运行真实实现。50,000 笔合成成交，一个合约/一个结果、七日时间跨度：

| 项目 | 结果 |
|---|---:|
| 导入与准备 | 0.876 秒 |
| 聚合全部 2,001 桶 | 1.333 秒 |
| 五档事件复盘 | 0.260 秒 |
| 聚合表、索引及 TOAST | 1,138,688 B |
| 原始标准化成交表及索引 | 19,816,448 B |
| 进程峰值 RSS | 91.1 MiB |

这里的“原始标准化成交表”是合成的结构化行，不是完整的真实响应 Parquet。聚合约 569 B/首版本桶；以 40 合约、两个结果、每日 288 桶的密集上限估算，七日约 87.5 MiB。此估算不含额外修订、分页观察、钱包、目录、案件、WAL 和 raw。不能由单合约合成数据推导全平台吞吐或长期日增量。

[完整测量](surveillance-event-review-benchmark-2026-10-29.json)；复现命令见 `surveillance/README.md`。临时测试/压测 schema 在 finally 中删除，不保留临时服务。

## 验证与边界

48 项调查测试覆盖迟到数据旧版本、公告边界、采样空/未知、同事件去重、大事件限额及单合约模式、钱包截断与准入、原分数保留、历史重建、容量依赖及现有采集恢复。既有 54 项后端测试、70 项 UI 单元测试、前端类型和构建也通过。

这是一条可复核的描述性调查路径，尚无经过标注样本校准的事后异常评分；这些字段为 null。自动新闻/比赛采集、跨平台规则等价、CUSUM/EWMA 和误报率校准尚未实现。原生事件关系也只覆盖本库已知成员；不足不能当作反证。钱包首次索引时间不是开户日期，现金周转不是净仓位或收益。

传统市场的方法依据及研究边界见此前 `tmp/traditional-surveillance-2026-10-29/REPORT.md`；本次实现不宣称复制监管机构的私有账户、订单或身份监控能力。
